# OnlyShell 终端兼容性与性能验收清单

本清单用于版本验收、回归和性能对比。每轮测试保存一份结果，避免只凭“感觉流畅”判断。

## 1. 测试环境与记录

### 环境要求

- OnlyShell Windows x64 安装包，记录版本号、安装包类型（Self-contained / Framework-dependent）和构建提交号。
- 一台可丢弃/可恢复的 Linux 测试主机，建议 Ubuntu 22.04/24.04 或 Debian 12；不要在生产服务器执行压力项。
- SSH 使用密钥认证优先；测试机预装 `bash`, `vim`, `less`, `tmux`, `htop`（或 `top`）、`python3`, `locale`, `ncurses-term`。
- Windows 记录版本、CPU、内存、显示缩放比例、OnlyShell 终端字体和字号。
- 同一轮性能对比固定 Windows 电源模式、网络、终端尺寸、字号、字体、scrollback 行数和主机负载。

Linux 准备命令（Debian/Ubuntu）：

```bash
sudo apt-get update
sudo apt-get install -y bash vim less tmux htop python3 locales ncurses-term
locale
```

## 2. 自动化基线

在仓库根目录运行：

```powershell
dotnet test .\TerminalPoc\VirtualTerminal-upstream\VirtualTerminal.Tests\VirtualTerminal.Tests.csproj -c Release
```

记录通过/失败测试数、耗时和完整日志。此项验证 VT 解码器、屏幕缓冲等单元行为，不代表 SSH 端到端兼容，也不测 WPF 实际渲染性能。

## 3. SSH 协商与终端基本信息

在 OnlyShell 打开 SSH 终端后，在远端依次执行并记录输出：

```bash
printf 'TERM=%s\n' "$TERM"
printf 'locale=%s\n' "$LANG"
printf 'colors='; tput colors 2>&1
infocmp "$TERM" >/dev/null 2>&1; printf 'infocmp_exit=%s\n' "$?"
stty size
```

验收：

- `TERM` 非空，远端 `infocmp "$TERM"` 成功；应用声明的终端类型与远端 terminfo 能力匹配。
- `stty size` 与应用终端实际列/行数一致；拖动窗口尺寸时远端程序同步重排。
- 如果当前协商的是 `xterm`，要单独记录 `tput colors` 是否为 8/256 及实际颜色表现。OnlyShell 当前 SSH ShellStream 使用 `xterm`，不能仅凭应用内部支持 ANSI 就认为远端获得了 `xterm-256color` 能力。

## 4. 交互式程序兼容性

每项均在 SSH 会话内执行；启动前确保测试机上没有需要保留的同名临时文件。

### 4.1 Shell 与基本按键

执行：

```bash
printf 'line1\nline2\n'
pwd
sleep 2
```

检查命令回显、提示符、回车、退格、左右/上下方向键、Home/End、Ctrl+C（中断 `sleep`）、Ctrl+L（清屏）和窗口缩放。不要在有选中文本时测试普通 Ctrl+C，因为它的语义可能是复制；另测产品定义的复制快捷键。

### 4.2 `less` / `man` 全屏和返回

```bash
man bash
```

检查全屏进入/退出、上下翻页、搜索 `/shell`、`n`/`N`、`q` 返回 shell；退出后提示符和屏幕状态正常。

### 4.3 `vim` 光标、编辑和颜色

```bash
vim /tmp/onlyshell-terminal-check.txt
```

在 vim 中依次测试方向键移动、`i` 输入中英文、Esc、`:wq`。重复打开后试 `/check` 搜索、`n`、`:set number`。文件仅为临时验收文件，可在完成后删除。检查光标定位、状态栏、颜色和退出后的 shell 恢复。

### 4.4 `tmux` alternate screen 与重连前检查

```bash
tmux new -s onlyshell-check
```

测试 `Ctrl+B` 后按 `%` 分屏，输入命令，调整窗口大小，切换 pane，`exit` 退出 pane，最后 `exit` 退出 tmux。测试完成前不要断开 SSH。验收：alternate screen 进入/退出正常、分屏无字符残影、尺寸变化后布局正确。

### 4.5 `htop` / `top`

```bash
htop
```

测试方向键、F 键（尤其 F10 退出）、搜索/排序以及窗口缩放。无 htop 时运行 `top` 并用 `q` 退出。

## 5. 字符、颜色、控制序列和鼠标

### 5.1 UTF-8、宽字符和 emoji

```bash
printf 'ASCII | 中文 | 日本語 | 한글 | emoji 😀 🚀 | combining é\n'
printf 'A中文B\n0123456789\n'
```

检查每个字符无乱码；中文/日文/韩文后的 `B`、列对齐和光标位置正确；emoji 不造成持续列偏移。对同一行连续输入中英文并用左右键移动，确认光标落点合理。不同字体分别记录结果。

### 5.2 ANSI 颜色与样式

```bash
python3 - <<'PY'
for i in range(16):
    print(f'\033[38;5;{i}m{i:3} foreground\033[0m', end='  ')
    if i % 4 == 3:
        print()
print('\n\033[1mbold\033[0m  \033[4munderline\033[0m  \033[7minverse\033[0m')
PY
```

检查 16 色、粗体、下划线、反显和重置；文字不会把后续 shell 输出染色。若 `tput colors` 宣称 256 色，再检查扩展色：

```bash
python3 - <<'PY'
for i in range(16, 256):
    print(f'\033[48;5;{i}m  ', end='')
    if (i - 15) % 24 == 0:
        print('\033[0m')
print('\033[0m')
PY
```

### 5.3 清屏、滚动区与鼠标模式

```bash
for i in $(seq 1 40); do printf 'row %02d\n' "$i"; done
```

检查向上滚动、回到底部、搜索终端历史、清屏后回滚内容的预期行为。再在 `htop` 或 tmux 中试点击/滚轮（若程序启用鼠标模式），确认应用是否把鼠标事件转发给程序；按住 Shift 测试本地选择/复制通路。

## 6. 键盘、复制、粘贴与搜索

- 在 shell、vim、less、tmux 分别测试 Enter、Tab、Esc、方向键、Home/End、PageUp/PageDown、Delete、Backspace、Ctrl+C、Ctrl+D、Ctrl+Z、Ctrl+R、Ctrl+L、Alt+字符。
- 验证产品快捷键复制/粘贴；复制英文、中文、跨行选区。检查换行和空格不丢失。
- 粘贴单行命令后确认不会自动执行；粘贴多行时应出现产品的确认保护，取消后不发送内容，确认后内容完整。
- Ctrl+F 搜索可见区和 scrollback 内的英文/中文，检查大小写行为、匹配高亮、上/下一项、无匹配提示和清除搜索。
- 在 vim/tmux 处于全屏时确认 Ctrl+F 等快捷键不会意外破坏前台交互；记录快捷键冲突。

## 7. Scrollback 与长输出

默认配置目标至少 10,000 行；项目终端缓冲默认值为 10,000 行，设置页可能允许用户修改。用以下命令生成带编号、可核对的历史：

```bash
python3 - <<'PY'
for i in range(1, 12001):
    print(f'ONLYSHELL_SCROLLBACK_{i:05d}')
PY
```

检查最后一行、向上滚动到最早保留行、搜索 `ONLYSHELL_SCROLLBACK_00001` 和 `_02000`。若配置 10,000 行，最早行可能因可视区/缓冲实现边界而不恰好为 00001，应记录实测保留范围；确认历史上限稳定，不随重复输出无限增长。连续滚动、拖动滚动条/鼠标滚轮时观察是否卡顿或短暂冻结。

## 8. 性能压测

### 8.1 固定条件与运行方法

先空闲 2 分钟记录任务管理器 OnlyShell 的 CPU、内存基线。分别运行 1 MiB、10 MiB、100 MiB 三档；每档至少运行 3 次，间隔 30 秒，记录中位数。保持相同终端尺寸、字体、字号、scrollback 和网络路径。

测试纯文本输出（每行约 100 字符）：

```bash
python3 - <<'PY'
import sys
line = '0123456789abcdef' * 6 + '\n'
target = 1 * 1024 * 1024
written = 0
while written < target:
    sys.stdout.write(line)
    written += len(line)
PY
```

把 `target` 分别改为 `10 * 1024 * 1024` 和 `100 * 1024 * 1024`。ANSI 场景可将循环里的行替换为 `"\033[32m" + line + "\033[0m"`，但按发送字符总量记录档位。若通过 SSH 运行，另记录 RTT 和实收大小。测试命令以运行完成、最后输出可见、shell 可继续响应为准。

每次记录：

| 指标 | 记录方法 |
|---|---|
| 完成时间 | PowerShell `Measure-Command` 仅测不到远端完成；以终端开始/结束墙钟时间记录，重复 3 次取中位数 |
| 输入响应 | 输出期间尝试 Ctrl+C；记录按键到输出停止/提示符恢复的时间。另在空闲时输入短命令观察回显 |
| UI 响应 | 测试期间切换页面、拖动窗口、打开设置/菜单；记录冻结、掉帧和操作延迟 |
| CPU / 内存 | Windows 任务管理器或资源监视器每 5 秒采样，记录峰值与结束后 1 分钟值 |
| 缓冲正确性 | 检查末尾标记、搜索、滚动和取消后是否可继续输入 |

**建议先作为版本间比较基线，不应将单台电脑结果当作普适承诺。** 初始目标：无输出时空闲 CPU 低且稳定；10 MiB 输出不崩溃、不中断输入事件循环；100 MiB 输出可用 Ctrl+C 在合理时间内停止并恢复输入；输出结束后 1 分钟内内存回落或趋稳。首次运行先记录基线，再为各项制定数值门槛。

### 8.2 输入回显延迟（SSH）

禁止用 `ping` 直接代替按键到屏幕延迟。分别在同网段和典型远程网络测量：

1. 先记录 `ping -n 20 <主机地址>` 的平均/最大 RTT（Windows）或 `ping -c 20 <主机地址>`（Linux）。
2. 在远端 shell 输入一组 20 个短标记，例如 `echo OS_LATENCY_01`，每条等待回显后再输入下一条；用屏幕录像逐帧观察按键到字符出现，或用高帧率录像人工计时。
3. 至少 20 次，报告 p50、p95、最大值；分别报告本地 PowerShell 与 SSH。SSH 延迟同时报告原值和“延迟减 RTT”的估算值，并说明它只是粗略分解。
4. 在空闲状态、1 MiB 输出期间、100 MiB 输出期间各测一组；输出期间再测 Ctrl+C 停止时间。

输入延迟建议初始目标：本地 shell p95 < 50 ms；SSH p95 不高于测得 RTT 加 50 ms（以相同网络基线比较版本）。如果不能逐帧可靠测量，标记为“估算”，不要报告虚假精度。

### 8.3 多会话与长时间运行

- 打开 1、5、10 个本地终端标签，随后按产品能力尝试 20 个；各会话每 10 秒输出一行计数，观察切换、输入、关闭行为。
- 对 SSH 多会话重复测试时，确保服务器负载允许；不能用单会话的 `sleep` 代替并发输出压测。
- 运行 30 分钟：每分钟切换标签、输入短命令、滚动；每 5 分钟记 CPU/RAM。记录是否持续增长、无响应、闪退、断连或输入丢失。
- 对 5 个会话各重复开关 20 次，检查关闭会话后进程/内存是否释放、其他会话是否仍能交互。

## 9. 验收矩阵与问题分级

优先级：

- **P0 阻断发布**：崩溃/挂死、无法输入或退出全屏程序、中文导致持续列漂移、Ctrl+C 无法中断、终端输出泄露到日志。
- **P1 必须修复或明确限制**：常见 vim/less/tmux/htop 功能异常、尺寸同步失败、scrollback 明显不足、粘贴保护失效、长输出造成持续 UI 冻结。
- **P2 可排期**：个别扩展控制序列、少见键盘布局、非关键渲染细节或低端网络下的性能问题。

版本通过条件：自动化测试通过；P0 为零；P1 均通过或有明确产品限制和复现说明；性能数据有同环境基线对比；所有“有降级/失败”项均有负责人和问题记录。
